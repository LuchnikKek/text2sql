# text2sql-api

Backend API для text2sql-агента на LangGraph. Учебный проект.

## Команды

- `uv sync` — зависимости. Только uv, никогда pip
- `uv run pytest -q` — тесты
- `uv run uvicorn app.main:app --reload` — dev-сервер (docs: /docs)

## Архитектура — что важно знать

- Слой агента спрятан за `app/agent/service.py::TextToSqlAgentService`
  (`run()` / `stream()`). API-код не знает о LangGraph; реализация агента —
  вне зоны ответственности этого репозитория, интерфейс не менять без согласования.
- Авторизация — чистый ASGI-мидлварь (`app/auth.py`), НЕ BaseHTTPMiddleware:
  тот ломает SSE-стриминг и ContextVar. person_id живёт в ContextVar
  (`app/context.py`). Swagger-схема HTTPBearer в `app/main.py` — только
  документация, реальные 401 отдаёт мидлварь.
- Наружу отдаём только `message_id` (UUID); внутренний автоинкрементный
  `id` из БД в контракты не попадает.

## Правила работы

- Существующие контракты ответов не менять и не переименовывать —
  новые поля только добавлять.
- Ошибки агента в /chat и /chat/sse НЕ превращать в 5xx: всегда 200,
  пользователю заглушка, техническая ошибка в `decision.error_message`.
  Это бизнес-требование, не баг.
- Любая правка кода: существующие тесты зелёные, новые случаи покрыты.
  В конце ОБЯЗАТЕЛЬНО выполнить проверку — используй skill `/verify`
  (или как минимум `uv run pytest -q`) и покажи результат.
- Минимальный дифф, без попутного рефакторинга. Проблемы за рамками
  задачи — сообщить, но не чинить.
- Новые зависимости — только после явного согласования.
- Конфигурация — через `app/config.py` (pydantic-settings) и env,
  никаких хардкоженных секретов.
