# Добавление источника обогащения

Источник по `entity_id` отдаёт `dict`, собирая его сам или через клиентов
из `app/clients`. Реестр (`app/enrichment/registry.py`) наполняется на
импорте модулей пакета, роутер `GET /api/v1/enrich/{source}/{entity_id}`
достаёт источник по имени. Добавление источника = один новый модуль
(плюс модуль клиента, если данные из внешнего API). Ничего другого
трогать не нужно.

У скилла два шаблона, оба копируются, а не сочиняются заново:

| Шаблон | Куда | Когда |
|---|---|---|
| `assets/source_template.py` | `app/enrichment/<name>.py` | всегда |
| `assets/client.py` | `app/clients/<name>.py` | если данные из внешнего API |

## Что выяснить до кода

Если не сказано в запросе — спросить, не додумывать:

1. **Имя в реестре** — оно же сегмент URL (`courses`, `employees`).
2. **Откуда данные**: мок/статика на первое время или внешний API (тогда —
   какой base URL, какие ручки, нужен ли новый клиент в `app/clients` или
   подойдёт существующий; источнику можно вызывать несколько клиентов).
3. **Форма `data`** — какие поля отдаём наружу.
4. **Пример `entity_id`** и что считается «сущности нет».

## Шаги

### 1. Скопировать шаблон источника

```
.claude/skills/add-datasource/assets/source_template.py
  → app/enrichment/<name>.py
```

Копировать, а не писать с нуля. Причина не в экономии печати:

- **Инварианты слоя не восстанавливаются по памяти.** Их четыре, и каждый
  ломается молча: регистрация именно на импорте модуля; `dict(...)` —
  возврат копии, иначе вызывающий мутирует наши данные; `EntityNotFound`
  против общей `EnrichmentError` (роутер разводит их в 404 и 502 — перепутать
  значит отдавать 502 на опечатку в id); совпадение с `Protocol` по форме,
  без наследования.
- **Написанный с нуля модуль выглядит правильным и проходит happy-path.**
  Расхождения всплывают на границах: чужой мутации, чужом 404, дубле имени.
- **Шаблон делает шаг механическим** — «заполнить TODO», а не «вспомнить
  архитектуру». Проверяемо: непроставленных TODO не осталось.

Дальше: переименовать класс (`TemplateSource` → `<Name>Source`), проставить
`name`, заполнить TODO, удалить неиспользуемый вариант `fetch()`.
Ориентир живого источника — `app/enrichment/courses.py`.

### 2. Реестр — руками ничего не подключаем

`app/enrichment/__init__.py` импортирует модули пакета сам, так что от
источника нужно только одно: вызов `register(<Name>Source())` внизу файла.
Забыть его всё ещё можно, но это ловит тест-сторож
`test_every_source_module_registers_a_source`.

Что накладывает автоимпорт:

- модуль источника импортирует `app.enrichment.base` / `.registry`,
  но **не** сам пакет `app.enrichment` — иначе циклический импорт;
- вспомогательный модуль внутри пакета называем с префиксом `_`
  (`_utils.py`), иначе автоимпорт сочтёт его источником;
- импорт пакета не должен ничего открывать: сокеты и соединения —
  лениво, при первом запросе (так устроен `RestClient`).

### 3. Скопировать шаблон клиента (только если данные из внешнего API)

```
.claude/skills/add-datasource/assets/client.py
  → app/clients/<name>.py
```

HTTP в источнике руками не пишется. Шаблон копируется по той же причине,
что и шаблон источника: инварианты здесь тоже молчаливые — `model_config`
подкласса мержится с родительским (в подклассе нужен только `env_prefix`,
и он же задаёт имена env-переменных); статусы и сетевые сбои разбираются
единственный раз в `RestClient._request`, а не в каждом клиенте; соединение
поднимается лениво и закрывается через `aclose_all()` в lifespan.

Дальше: переименовать классы (`TemplateClient` / `TemplateClientSettings`),
проставить `name` и префикс, заполнить TODO, добавить по методу на ручку.
Живой ориентир — `app/clients/courses.py`.

Клиент бросает `RestClientNotFound` / `RestClientError`, источник переводит
их в `EntityNotFound` / `EnrichmentError`; про обогащение клиент не знает и
`app.enrichment` не импортирует. Настройки клиента живут рядом с клиентом,
а не в `app/config.py`; хардкоженных URL и секретов в модулях быть не должно.

### 4. Тесты

Дописать в `tests/test_enrich.py`, повторяя тамошний стиль:

- `fetch()` на существующем id → ожидаемый `dict`;
- `fetch()` на неизвестном id → `pytest.raises(EntityNotFound)`;
- если источник ходит в API — клиент строится с `httpx.MockTransport`
  и передаётся в конструктор источника (образец сборки клиента поверх
  мок-транспорта — `tests/test_clients.py::make_client`); сбой внешней
  системы (500) → `pytest.raises(EnrichmentError)`;
- источник в `source_names()` после импорта пакета;
- `GET /api/v1/enrich/<name>/<id>` через фикстуры `client` + `auth_headers`
  → 200 и точный JSON.

Регистрируешь что-то вручную в фикстуре — снимай через `unregister()`
в teardown, иначе следующий тест упадёт на дубле имени.

Завёл клиента — покрой его в `tests/test_clients.py`: дефолты `url`/`timeout`
и чтение их из env по своему `env_prefix`, 404 → `RestClientNotFound`,
500 и таймаут → `RestClientError`.

### 5. README

Перечислить источник: имя, что отдаёт, пример `entity_id`. Раздела про
источники обогащения может ещё не быть — тогда завести и заодно внести
`/api/v1/enrich/{source}/{entity_id}` в таблицу эндпоинтов.

### 6. Проверка

Выполнить skill `/verify` (минимум — `uv run pytest -q`), показать результат.
Затем пройти по `references/checklist.md` и отчитаться по пунктам. Шаг
не «готово», пока чек-лист не закрыт целиком.

## Границы

- Контракт `EnrichResponse` не менять — только форма `data` у нового источника.
- `base.py`, `registry.py`, `routers/enrich.py` при добавлении источника
  не правятся. Понадобилось — значит задача другая: остановиться и сказать.
- Ошибки внешней системы поднимать как `EnrichmentError`, не глушить:
  502 здесь — правильный ответ (правило «ошибки агента → 200» относится
  к `/chat`, к обогащению оно не применяется).
